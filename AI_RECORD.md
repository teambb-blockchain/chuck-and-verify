# AI Record

Log of AI-assisted design and implementation for this project.

## How to use

Add an entry whenever AI tools help with architecture, code, docs, or debugging in a meaningful way.

If an entry is written after the work, rather than during it, add a **Recorded:** line saying so and naming the source it was rebuilt from (a commit, a review document, transaction receipts). Leave out anything that source does not show. In particular, do not write "Nothing found" under **What it got wrong** unless someone checked at the time; write that it was not recorded. A reader can then tell which entries were logged as the work happened and which were reconstructed.

### 2026-11-08 — Wallet sign-in failing on the DIDLab host

- **Tool:** Claude Code
- **Request:** Sign in on `https://teambb.didlab.org` showed "Sign-in failed: Request failed." Find the cause and fix it, changing the code rather than the container's nginx config
- **Outcome:** The code worked locally. Every `/api/*` route on the live site returned a plain-text `404 Not found`, while the new frontend files loaded. Diagnosis on the host, in order: an old `node index.js` held port 3000, so a new copy crashed with `EADDRINUSE`; killing it let the supervisor restart Node from `/srv/app`, a deployed copy rather than a git checkout, which already had the current code; `curl localhost:3000/api/me` inside the container returned the correct JSON. The cause was the container's nginx: `location /api/ { proxy_pass http://127.0.0.1:3000/; }`. The trailing slash strips the prefix, so `/api/me` reached Node as `/me` and got Node's own 404. nginx also does not forward `Host`, so Node sees `127.0.0.1:3000`. Code changes: `index.js` adds `/api` back for the API routes only (`/me`, `/auth/*`, `/admin/users[/…]`, `/ipfs/add`), and unprefixed paths still work for local `npm start`. `server/auth.js` replaces `requestHost` with `requestSite()`: it uses `X-Forwarded-Host` or `Host` when they name a real domain; when they are loopback, it uses the browser's `Origin`, but only if it is on the `PORTAL_ORIGINS` allowlist (default `https://teambb.didlab.org`). The result sets the sign-in message domain, the `URI:` scheme, and the cookie's `Secure` flag. Without the allowlist, a look-alike site relaying requests could get a message carrying its own domain, and the wallet would not warn. `frontend/public/session.js` shows the HTTP status instead of the generic "Request failed."
